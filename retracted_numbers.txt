# Numbers a NAMED LINE in a NAMED file is entitled to QUOTE without asserting.
#
# WHY A LINE HASH, AND NOT A WORD LIST.
# v1 exempted anything after a quotation mark. v2 wanted "retraction language on the line" — and I
# deleted that logic while keeping the comment describing it, so v3 exempted a registered NUMBER
# wherever it appeared in its file. v4 wired the word list back up, and an adversary defeated it in
# one sentence: "...every one of them closed and independently machine-checked. NOTHING HERE IS
# RETRACTED." The word `retracted` matched. A keyword list cannot tell "this was retracted" from
# "nothing here is retracted", because negation reuses the word.
#
# So the exemption stops describing the line and starts NAMING it. Each entry pins the sha256 of the
# exact line the quotation lives on. Edit that line and the exemption lapses; write a new sentence
# containing the same digits and it is not exempt at all. This is the shape of the one mechanism in
# this artifact that has never been defeated — closure.py's blockquote registry — which pins bytes
# rather than matching patterns.
#
# format:  <file> | <number> <unit> | <sha256[:16] of the stripped line>
LIMITS.md   | 41 proofs                  | f3ed3d3c7cca5462
LIMITS.md   | 999 labelled statements    | 1e3f82628e1cba8b
FINDINGS.md | 34 proofs                  | b707c8b281c4cf94
